How it works

A shared queue your team controls

Workers connect out

Your team hosts the coordinator and chooses the devices that join. Workers connect out, so contributors can take part without opening ports on their home routers.

Many devices share a batch

The coordinator assigns independent jobs to idle workers that can run the requested model. This works well for evaluations and batch prompts, where each worker can finish its own job.

Jobs can be retried

If a worker goes offline, the coordinator can put its unfinished job back in the queue. The dashboard tracks retries and completed results so you can see what happened.

Verification

Compare answers across devices

The coordinator can send sampled prompts to a second worker running the same model with a fixed seed and compare the response hashes. A mismatch gives contributors an example to reproduce and investigate.

Experimental training

Can spare computers help fine-tune a model?

OserAI is testing DiLoCo with LoRA. Workers train locally for several steps before sending adapter updates, reducing how often they need to communicate. Live training rounds currently use invited, trusted devices.

Contributor testing

Help test OserAI on real hardware

We’re looking for people with laptops, Macs, and gaming PCs to run one inference job and tell us what happened. A failed run can reveal as much as a successful one.

Open the quickstart Contribution guide

  1. Set up one computer

    Install Python 3.11 or later and Ollama. Run ollama pull llama3.2:1b.

  2. Run one local job

    Use the quickstart to start the coordinator and worker on one device. Submit one prompt, then open View results in the dashboard and check for completed.

  3. Report what happened

    Include your OS, CPU or GPU, RAM, and the result or exact error. Share your test result on GitHub.
